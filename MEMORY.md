## Architecture Notes

- Proposed two-speed evolutionary pipeline:
  1. Encode a 60-card Historic deck as constrained integer counts, lock identity anchors such as four `Parallel Lives` and four `Mythos of Illuna`, and repair every mutation back to legality, color-source, and deck-size constraints.
  2. Run cheap deterministic goldfish screens for mana failure, mulligans, turn-three Lives, turn-four Mythos, turn-four/five lethal, dead draws, and disruption recovery. Use common random seeds and successive halving to discard weak candidates cheaply.
  3. Run survivors against a fixed 6-10 deck Historic gauntlet in HexDek, with two-player/non-Commander settings, paired play/draw seeds, confidence intervals, caching, and penalties for aborts/timeouts.
  4. Evolve with package-aware swaps and DEAP NSGA-II or MAP-Elites. Optimize several objectives rather than one raw win rate: average gauntlet win rate, worst matchup, speed, mana reliability, resilience, deck identity, and optional wildcard cost.
  5. Preserve a Hall of Fame and test candidates against earlier champions to prevent cycling. Cross-check finalists in Phase and Forge/XMage, then validate a small set in Arena.
- Start with a curated 50-150 card candidate pool; searching every Historic card immediately makes the discrete search space impractically large. Expand later using card tags, co-occurrence, or a deck-completion model such as Manamorphosis.
- Use package-aware mutations (one-card paired swap, count step, ramp/payoff/protection package swap, land-spell trade, mana-base retune) and a repair operator rather than arbitrary crossover.
- Simulator-exploit controls: unit-test critical card interactions, compare finalists across engines, never score timeouts as wins, version every result by engine build, and cache `(deck hash, opponent, seed, play/draw, engine version)`.
- 2026-08-29 implementation direction: Rust workspace with a simulator-independent `evolver-core`, Tauri v2 command/event shell, and a lightweight TypeScript/Vite frontend. The core owns genomes, legality, repair, deterministic mutation, parallel evaluation, fitness/Pareto data, and MTGA export; simulator and card-catalog services sit behind traits.
- Store the compact MTGA card catalog and image cache under the operating-system application-data/cache directories, not in Git. Use Scryfall bulk data, filter to Arena-supported printings (`games` includes `arena` and an Arena identifier where available), import to SQLite, then delete the raw bulk download.
- Start with CPU-parallel evaluation using Rayon. The host has an AMD Ryzen 9 9950X3D (16 cores/32 logical), 61.6 GiB RAM, and an NVIDIA RTX 3090 with 24 GiB VRAM (last verified 2026-08-29). Reserve GPU support for batched learned surrogate/policy models; irregular rules simulation is initially better suited to CPU workers.
- The deck model must use explicit zones, including a command zone, rather than assuming every format is a 60-card mainboard plus sideboard. Platform availability (`arena`, `paper`, `mtgo`) and format legality are independent filters.
